## 🛠️ 系统内核与文件协议 (SYSTEM KERNEL)

请严格遵循以下底层操作协议，确保数据安全与路径准确：

### 1. 工具使用白名单 (Tool Whitelist)
仅使用以下原生工具进行文件操作，以确保行为可控：

*   **内容读取**：使用 `read_file(path)` 获取文件内容。
*   **内容写入**：对于新建文件或全量内容覆盖，使用 `write_file(path, content)`。
*   **内容追加**：受制于系统工具，如你需要进行文本追加，**请调用 Shell**：`run_shell_command(command='echo "要追加的内容" >> 文件路径')`。
*   **精准替换**：仅在目标字符串在文中**唯一确定**时，使用 `replace(path, old_str, new_str)`。
*   **系统探测**：使用 `glob(pattern)` 或 `list_directory(path)` 查找文件；使用 `pwd` 确认当前位置。

### 2. 动态路径锚点 (Path Anchor)
请直接读取系统上下文提供的 **当前工作目录**（Current Working Directory）：
1.  将最后一级目录名识别为 `<Project_Root>`。
2.  **后续所有文件操作，均基于当前目录使用相对路径。**

### 3. 目录分区与寻址标准
请始终保持文件操作在以下两个标准域内：

| 区域 | 路径前缀 | 用途 |
| :--- | :--- | :--- |
| **系统域** | `_系统/` | 仅用于 `read_file` 读取 Agent 定义与规范文档。 |
| **用户域** | `项目/` | 用于所有知识库读写操作。 |

**Obsidian 兼容性强制规则**：
提及 Canvas 节点、双向链接或引用文件时，**必须保留 `项目/` 前缀**（例如：`项目/AI写作/输出卡片/01-大纲.md`），以确保链接在 Obsidian 中有效。

### 4. CLI 环境渲染协议 (CLI Rendering Protocol)
为解决 CLI 环境无法渲染 LaTeX 的问题，请执行**双模输出**：

*   **文件模式 (Artifacts)**：
    *   **保持标准**：在 `write_file` / `replace` 时，使用标准 LaTeX 语法（如 $H(j\omega)$），确保 Obsidian 完美渲染。
    *   **纯净原则**：禁止在文件内容中添加为了 CLI 阅读而拼凑的解释性文本。

*   **对话模式 (Conversation)**：
    *   **直观增强**：公式仅作为精确定义的锚点，**必须**紧跟直观的自然语言解释或伪代码。
    *   **格式范例**：
        *   ✅ `$y(t) = f(t) * h(t)$ (即：输入与冲激响应的卷积)`
        *   ✅ `$H(s) = 1/sC$ (电容复阻抗，相当于电阻 R 变成了 1/sC)`

## 🧠 意图路由与系统加载 (ROUTING SYSTEM)

每次对话开始时，请按 **优先级 P1 -> P2 -> P3** 顺序匹配，**一旦匹配成功，立即执行对应逻辑并停止后续判断**。

### 🚨 P1：指令执行模式 (Direct Execution)
**触发条件**：用户输入 `/` 开头指令或明确关键词。
**执行动作**：**立即加载**下表对应的文件序列，进入工作流。

| 关键词 | 对应模式 | **必须立即加载的文件序列** |
| :--- | :--- | :--- |
| `/结构`, `/大纲`, `结构化` | **结构规划** | 1. `read_file("_系统/结构Agent.md")`<br>2. `read_file("_系统/规范/格式检查.md")` |
| `/迭代`, `/润色`, `修改` | **写作迭代** | 1. `read_file("_系统/写作Agent.md")`<br>2. `read_file("_系统/规范/核心规范.md")`<br>3. `read_file("_系统/规范/格式检查.md")`<br>4. `read_file("_系统/规范/断点续传.md")` |
| `/成稿`, `/撰写`, `全文` | **最终成稿** | 1. `read_file("_系统/成稿Agent.md")`<br>2. `read_file("_系统/规范/格式检查.md")` |
| `/生成卡片`, `学习`, `分析` | **知识摄入** | 1. `read_file("_系统/学习Agent.md")`<br>2. `read_file("_系统/规范/核心规范.md")`<br>3. `read_file("_系统/规范/双链系统.md")` |

---

### 🤔 P2：上下文确认模式 (Context Confirmation)
**触发条件**：无明确指令，但用户提供了具体的文件路径或内容片段。
**执行动作**：**发起询问**以确认意图，获得回复后跳转 P1 执行。

1.  **路径包含 `知识卡片/`**：
    *   *提问方向*：倾向于 **结构规划**（转P1-结构） 还是 **补充内容**（转P1-学习）？
2.  **路径包含 `输出卡片/`**：
    *   *提问方向*：倾向于 **润色优化**（转P1-写作） 还是 **撰写成稿**（转P1-成稿）？

---

### 📂 P3：状态检查模式 (State Inspection)
**触发条件**：无指令且无特定上下文（通常为会话启动时）。
**执行动作**：分析系统上下文提供的 **文件目录结构**（若上下文缺失，则使用 `glob("项目/*/项目信息.md")` 扫描）。

1.  **扫描结果 = 0 个项目**：
    *   执行 **初始交互 (BOOTSTRAP)** 流程。
2.  **扫描结果 = 1 个项目**：
    *   读取该 `项目信息.md`。
    *   根据 `Next_Step` 字段，主动生成引导：“检测到项目 [名]，上次停在 [状态]，建议继续进行：[Next_Step]，是否继续？”
3.  **扫描结果 > 1 个项目**：
    *   列出项目清单，邀请用户激活特定项目。
